# NexaFunds Analysis AI — Learning Backend

Real backend for NexaFunds: historical learning + supply/demand + smart channel detection + market regime + risk-aware signal generation.

## Install/run
`py -m venv .venv`
`.venv\\Scripts\\activate`
`pip install -r requirements.txt`
`py main.py`

## Train from MT5 history
Export chronological OHLCV CSV with columns `timestamp,open,high,low,close,volume`, then:
`py train_model.py your_history.csv --version model_001`

The classifier trains on causal indicator, confirmed-swing, repeated-level, candle-rejection, and liquidity-sweep features. Direction labels require the target barrier to be reached before the opposing stop; same-candle barrier conflicts are marked no-edge. Chronological holdout and walk-forward validation purge the 12-candle label horizon, and model promotion additionally requires minimum out-of-sample precision, recall, and support for both reversal directions. Normal classifier training also fits grid-spacing and buy/sell swing stop/target regression heads from future excursion labels and reports their holdout MAE in ATR units. These estimates are not a guarantee of execution quality; the consensus API's active risk profiles remain fixed. Failed candidates do not replace the active model. These checks reduce leakage and weak-model promotion but do not guarantee profitable trading.

The trained H1/M15 pivot-reversal candidates were force-promoted despite failing validation gates; their recorded metrics and failed gates are included with the model artifacts and registry. This is an explicit operator override, not evidence that either model is reliable or profitable. In particular, reversal precision is weak, so do not treat these predictions as trustworthy live-trading signals. The predictor maps the expanded live feature set onto older model feature schemas so model loading remains backward-compatible; old models do not gain the new reversal features without being retrained.

H1 and M15 trend bias is predicted by a separately trained three-class ML model using the same causal market-feature pipeline as the setup classifier. Its historical targets classify the trailing 500 closes using an ATR-normalized price-path regression as `BUY`, `SELL`, or `RANGE`; the API does not manufacture a `NONE` trend by combining EMA votes. `RANGE` is an explicit model class and means the observed path does not meet either directional label threshold. This longer window is slower to turn and is a regime estimate, not an entry-timing signal. Trend artifacts trained with the previous 50-candle labels are rejected by the predictor and must be retrained before trend predictions are available. H1/M15 trend requests and H1/H4 consensus inputs require at least 500 valid completed candles; lower-timeframe entry inputs retain the existing 260-candle minimum. The trend-only training option evaluates a chronological holdout and saves an independent artifact without replacing the setup classifier:

`py train_model.py data/XAUUSD_m_H1.csv --trend-only --version xauusd_h1_trend_500_20261018`

The 500-candle trend model at `models/xauusd_trend_500_directional_20261019.joblib` is the active default for H1, M15, H4, and the six-timeframe H1 trend path by explicit operator override. It was trained on XAUUSD data only, so its use on other instruments is not validated. Its grouped/purged chronological holdout balanced accuracy was 0.475 (below the 0.55 gate); it identified 0 of 39 RANGE holdout cases, so the model is strongly directional and experimental, not a validated or reliable trading signal. Environment variables `NEXA_H1_TREND_MODEL_PATH`, `NEXA_M15_TREND_MODEL_PATH`, `NEXA_SHARED_TREND_MODEL_PATH`, `NEXA_H4_TREND_MODEL_PATH`, and `NEXA_H1_MULTI_TREND_MODEL_PATH` can override the default. The older 50-candle artifacts remain incompatible.

Trend-only candidate training supports `--trend-class-weight balanced` (the default) and `--trend-class-weight none`, plus `--trend-range-weight-scale` to reduce the balanced RANGE class weight while keeping neutral labels. Compare candidates with `--candidate-only` and grouped, purged chronological metrics before selecting an artifact. These options apply only to the separate trend classifier; do not choose a candidate solely because it predicts fewer RANGE labels. The currently active XAUUSD-only candidate was selected as an explicit operator override despite failing validation.

Trend model quality is reported on the chronological holdout and is not a guarantee of accurate live direction. The consensus API waits for directional setup confluence before planning an entry. A counter-bias swing is allowed only when its entry models classify a reversal or failed breakout; disagreement without one of those learned setup classes remains `WAIT`. For the EA's six-timeframe route, the selected entry POI must come from a validated, mode-specific execution model: the model predicts whether to trade, the entry offset and width, and stop/target distances from current features. The API does not substitute structural supply/demand areas or swing references when that model is missing, rejected, or disagrees with the setup direction. It returns `WAIT_FOR_ML_POI` in that case. A valid plan still waits for its learned POI to be touched, and the EA checks that the live quote remains inside it before opening a position. Buy/sell probability totals remain in the API for backwards compatibility but are not used to choose the trade direction or shown as the EA's directional decision.

The EA's six-timeframe consensus request uses H4 for overall context and H1 for the current regime. For directional entries, H1 must predict BUY or SELL at or above `NEXA_TREND_MIN_CONFIDENCE` (default 0.55); H4 disagreement is informational and does not block an otherwise valid trade. M1 and M5 setup models must agree with H1 for a directional scalp; M15 and M30 setup models must agree with H1 for a swing entry. When H1 explicitly predicts RANGE at or above the same confidence threshold, M1 and M5 must agree on a direction; the validated scalp execution model then supplies the learned POI. The range scalp uses the same non-zero stop-loss and scalp confidence/risk gates; it does not enable swing entries against a range. The request can select `AUTO`, `SCALP`, or `SWING`; AUTO prefers a confirmed swing and otherwise uses a confirmed scalp, including a qualifying range scalp. The service waits when an entry model is missing, confidence is below the configured threshold, the paired entry models disagree, no validated execution plan agrees with the setup direction, or the learned POI has not been touched. The EA draws only validated model-generated POIs from the available timeframe execution models (H4, H1, M30, M15, M5, M1), separately labeled by timeframe. Structural supply/demand and swing-reference zones are not displayed as ML POIs. H4/H1 default to the pooled 500-candle trend artifact described above.

The six-timeframe route expects entry artifacts at `models/m1_entry_20261017.joblib`, `models/m5_entry_20261017.joblib`, `models/m15_entry_20261017.joblib`, and `models/m30_entry_20261017.joblib`, configurable with `NEXA_M1_ENTRY_MODEL_PATH`, `NEXA_M5_ENTRY_MODEL_PATH`, `NEXA_M15_ENTRY_MODEL_PATH`, and `NEXA_M30_ENTRY_MODEL_PATH`. Train a timeframe-specific candidate using only that timeframe's CSV and the corresponding barrier profile. For example, M1/M5 use `--stop-atr 0.7 --target-atr 1.0`; M15/M30 use `--stop-atr 1.0 --target-atr 1.5`. Use `--candidate-only` to avoid changing the active model registry, and inspect the saved chronological validation metrics and `promotion_rejections` before configuring an artifact for execution. The six-timeframe route uses stop/target distances from a validated execution model, constrained by mode-specific maximum stops and minimum reward/risk. The legacy H1/M15 route retains its fixed ATR risk profiles; neither learned nor fixed estimates guarantee execution quality. Scalp orders require a non-zero stop loss. The available local CSVs are XAUUSD-only, so they do not establish cross-instrument entry-model quality.

The current local timeframe entry candidates were trained from 2,000 chronologically distributed labels per timeframe, but all failed promotion gates (M1/M5/M15/M30 holdout balanced accuracy: 0.226/0.226/0.181/0.189; gate: 0.55). They remain experimental and are not treated as validated by the six-timeframe API. Separately learned execution-level model files are not currently present in the local `models` directory. Until validated per-timeframe execution models are trained and configured, the EA's six-timeframe service intentionally returns no actionable entry POI and cannot open new ML trades; it will not relabel a structural zone as ML output. Train a candidate from one timeframe's history with `py train_model.py backend/data/XAUUSD_M1.csv --execution-levels --execution-mode SCALP --version xauusd_m1_scalp_execution`, inspect its saved JSON validation metrics, and only configure an artifact whose `validation_status` is `passed`. The matching environment key is `NEXA_M1_SCALP_EXECUTION_MODEL_PATH`; the equivalent key pattern applies to other timeframe/mode pairs. The older pooled trend artifact's 0.815 balanced accuracy was measured against the previous trend-label definition and is not evidence for the new 500-candle labels. The active XAUUSD-only 500-candle trend model is configured by explicit operator request despite its 0.475 grouped/purged chronological balanced accuracy and zero RANGE recall; it has not passed the 0.55 validation gate and has no demonstrated cross-instrument accuracy. Trend accuracy is not an assurance of profitable entries.

The current H1/M15 reversal candidates were force-promoted despite failing validation gates, and their recorded reversal precision and recall are weak. The staged direction/confirmation flow makes those model outputs explicit and avoids trading without the expected confirmations; it does not improve the trained weights or guarantee a sharp reversal, accurate prediction, or profitable trade. Retrain and promote candidates only after they pass the documented out-of-sample validation gates.

The EA Logs tab records H4 overall direction, H1 current direction, lower-timeframe setup outputs, selected POI, entry-zone status, and the execution gate. Class scores describe model rankings; context cues are separate observable features, not feature attribution or proof of causation. The EA draws validated model-generated POIs on-chart and checks the current quote against the selected POI before opening a position. The remote panel's tab changes reuse its browser page, and its Settings tab adjusts the panel size and accent colour. Scalp grid spacing uses a trained direction-specific adverse-excursion estimate in ATR units when that regression model is available, bounded between the configured base spacing and three times that spacing; otherwise it explicitly falls back to the configured base interval. The EA title and embedded dashboard version are sourced from the same version constant. Dashboard initialization does not require terminal trading permission, and the EA creates the dashboard before making ML requests.

Set the website-issued account-bound license in `InpLicenseKey`. For ML access, set the Render `INGEST_API_KEY` in the EA's optional `InpMLApiKey` input (recommended for configuring a terminal without rebuilding the EA); if blank, the EA falls back to the `NEXA_ML_API_KEY` build-time definition, then `MQL5/Files/NEXA_ML_API_KEY.txt`. No real key is included in source. Credentials embedded in a compiled EA can be extracted, so do not distribute an EA containing a privileged/shared production key; rotate any key that has been shared or exposed. ML requests default to a 60-second timeout and a 5-second polling interval; both can be set in the EA inputs and adjusted on the dashboard, with the timeout capped at 60 seconds. These are synchronous POST requests to `https://nexa-funds-ai.onrender.com/api/ml/predict/consensus`; the prediction response itself verifies connectivity, authentication, and inference, so no extra health request is made before each prediction.

Non-2xx ML responses are written to the MT5 Experts log with the HTTP status, response-body excerpt, and available server/Cloudflare request-ID headers; the API key and candle payload are not logged. The prediction endpoint also logs each request and resulting HTTP status in Render with a generated `X-Nexa-Request-ID` response header; on an HTTP error, the EA includes that ID in its Experts log for correlation. No API key, candle payload, or client address is logged. If a matching request ID/log entry is absent after deploying the updated backend, verify that the Render service is deploying this repository and serving the consensus route.

The `InpLicenseKey` input is checked online at `https://nexafunds-steel.vercel.app/api/licenses/validate` and bound to the current MT5 account number, broker server, and account type. The Vercel route proxies to NexaFunds' existing license-validation API, which verifies the signature and active product/account record. The website license is checked at initialization and before starting trading; use the dashboard recheck button to check it again. In MT5, allow WebRequest access to both `https://nexa-funds-ai.onrender.com` and `https://nexafunds-steel.vercel.app`. An ML API HTTP 401 is shown as `ML AUTH REQUIRED`; an invalid/revoked/account-mismatched website license blocks trading.

### Remote HTML dashboard

The EA uses the web dashboard as its only chart panel; the native chart-object dashboard is disabled. The bitmap panel supports Trade, Strategy, Info, News, AI, Logs, and Settings tabs. MT5-native clickable tab buttons sit over the rendered tab labels, so tab switching does not depend on bitmap click hit-testing; Trade and strategy controls send actions to the EA, and Settings changes the accent colour and panel size. Drag the top title bar (not the tabs) to move the panel; Reset Position returns it to `InpDashboardPanelX` and `InpDashboardPanelY`.

Deploy the NexaFunds API with the `/api/mt5/panel.bmp` renderer and set its `MT5_API_KEY` and `PANEL_URL` environment variables (`PANEL_URL` must point to the frontend's `/ea-panel` page). Enter that same API key in `InpDashboardPanelApiKey`, keep `InpDashboardPanelUrl` pointed at the API renderer endpoint, and allow the API host in MT5 under Tools > Options > Expert Advisors > Allow WebRequest for listed URL. The panel defaults to chart position x=470, y=30. The remote renderer requires Puppeteer's Chromium runtime on the API host.

## API
`GET /health`
`POST /api/market/candles`
`GET /api/analysis/XAUUSD/M15`
`GET /api/channels/XAUUSD/M15`
`GET /api/supply-demand/XAUUSD/M15`

The analysis endpoints use their configured trend model for the requested timeframe. The EA consensus endpoint retains its H1/M15 compatibility path for older clients; requests containing all six candle arrays use H1 as the mandatory trade direction, treat H4 as optional context, and require M30/M15/M5/M1 entry confluence.

## NexaFunds
Use the existing Node/Express backend as a proxy: React -> NexaFunds API -> Python Analysis AI. The frontend can draw `analysis.primary_channel.upper/lower` and `analysis.supply_demand_zones` directly. The EA should consume the same analysis endpoint/JSON and enforce execution/risk limits separately.

## Learning loop
Every executed setup should be recorded in `learning.db` with its features, model version and eventual R-multiple. Retraining is controlled; do not replace the live model after every trade.
